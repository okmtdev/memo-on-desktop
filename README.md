# Daymark

今日の締め切りから今後の予定まで、仕事とプライベートのタスクをひとつの画面で管理するmacOSアプリです。プライベートのタスクはワンクリックで画面から隠せます。

## 必要なもの

- macOS 13 Ventura以降
- Xcode Command Line Tools（Swift 6.0以降）

## 起動方法

ターミナルでこのフォルダに移動して、次を実行してください。

```sh
./run.sh
```

Swiftでビルドした後、`~/Applications/MemoOnDesktop.app` を更新して起動します。起動中であれば再起動するため、常に今回ビルドした最新版が開きます。ビルドに失敗した場合は、起動中のアプリをそのまま残します。

メニューバーのチェックマークアイコンから「MemoOnDesktopを開く」を選ぶと、ウィンドウを表示できます。ウィンドウを閉じてもアイコンは残ります。終了するには、アイコンのメニューから「MemoOnDesktopを終了」を選んでください。

コードを変更した後は、以下でビルド・アプリの更新・再起動をまとめて行えます（`./run.sh` も同じ処理を実行します）。

```sh
./build.sh
```

ソースを変更していないときは、Finderのホームフォルダ内「アプリケーション」にある `MemoOnDesktop.app` を開くだけで起動できます。ログイン時の自動起動は設定しません。`swift build` 単独ではビルドのみとなり、インストール済みアプリは更新されません。

`run.sh` は、このMacのmacOSと同じメジャーバージョンのSDKがインストールされていれば、そのSDKを選びます。なければCommand Line Toolsの標準SDKを使います。`SDKROOT` を指定すると、そのSDKを優先できます。

### このMacで確認した環境

- macOS 26.7.1
- Apple Swift 6.4（Command Line Tools）
- macOS SDK 26.5

この環境では、通常の `swift run` はSDK 27.0を選び、`SwiftUIMacros` が見つからないエラーでビルドに失敗しました。`./run.sh` ではインストール済みのSDK 26.5を選びます。Mac全体の開発ツール設定を変更する必要はありません。

## 使い方

- 「タスクを追加」または `⌘N` でタスクを登録します。
- 追加時に「仕事」「プライベート」を選びます。Enterでも登録できます。
- タイトルをクリックすると、その場で直接編集できます。Enterまたはフォーカスを外すと保存し、Escで変更を取り消します。タイトルを空にはできません。
- 各タスク右側の鉛筆ボタンから、タイトル・分類・関連URL・締め切り・優先度をまとめて編集できます。「保存」で反映します。外側のクリックやEscで閉じても、編集中の内容はアプリ終了まで保持します。定期タスクの場合はその回だけに反映します。
- 優先度は「High」「Middle」「Low」から選べます。初期値と既存タスクは「Middle」です。登録後は各タスクの旗のメニューから変更できます。標準の並び替えでは、同じ締め切りの中をHigh → Middle → Lowの順に並べます。
- 締め切りは任意です。「締め切りを設定」からカレンダーで日付を選び、「設定」を押します。「今日」「明日」のショートカットも使えます。登録後も各タスクのカレンダーボタンから変更・解除できます。
- サイドバーの「マイビュー」から、保存したビューを切り替えます。固定の「今日」「今後」「期限なし」「完了済み」メニューはありません。最初は未完了タスクを表示する「マイビュー」が1つあります。
- 一覧上部の「フィルター」で状態（未完了・完了・すべて）・分類・優先度・期限を選びます。「並び替え」では期限・優先度・作成日・完了日を最大4条件まで設定し、上の条件が同じ場合に次の条件で並べます。検索と組み合わせられます。
- 並び替えの標準は「期限が早い順 → 優先度が高い順」です。「条件を追加」と各行の上下矢印・削除ボタンで組み合わせを変え、各条件の順序も反転できます。例：「優先度が高い順 → 期限が早い順 → 作成日が古い順」。期限未設定・完了日時不明のタスクは、その項目のどちらの順序でも末尾になります。全条件が同じ場合は作成が新しい順、さらに同じなら固定のID順で並べます。条件の順番と順序もビューに保存され、以前の単一ソート設定は従来の並び方を保って移行します。
- 条件を変更すると「未保存」と表示され、「保存」または `⌘S` でそのビューを更新します。「別名で保存」・サイドバーの「＋」・「… → 新しいビューとして保存」から、現在の条件を別のビューにできます。
- 検索・フィルター・並び順・予定の表示期間と表示条件をまとめて保存します。「…」から名前変更・保存した条件への復元・削除ができます。ビューを削除してもタスクは削除されません。変更途中の条件はビューごとに保持し、選択中のビューも再起動後に復元します。以前の保存ビューは自動で引き継ぎます。
- 締め切りに時刻はありません。年月日で保存し、当日は終日「今日が締め切り」と表示します。翌日から期限超過となります。
- 関連URLは任意です。Slack・Notionなどの `http://` / `https://` リンクを1件添付し、タスクから開けます。
- URLの「プレビュー」を押すと、一般ページのタイトル、連携済みSlackのメッセージ本文、連携済みNotionのページ本文の抜粋を表示します。取得できない場合もリンクから開けます。
- タスク入力画面は、アプリ内の外側をクリックするかEscapeで閉じられます。入力途中のタイトル・分類・URL・締め切り・優先度・繰り返し設定は、ウィンドウを閉じてもアプリを終了するまで保持します。登録すると入力内容をリセットします。
- 四角いチェックボックスで完了/未完了を切り替えます。「フィルター → 状態 → 完了」で完了タスクを表示できます。「並び替え → 完了日 → 新しい順」に並べ替えられ、各タスクにも完了日時を表示します。未完了に戻すと日時を解除し、再び完了にすると新しい日時を記録します。以前のバージョンで完了した日時不明のタスクは末尾に表示します。
- 左下の「プライベートを隠す」を押すと、プライベートのタスクと件数を画面から隠します。`⌘⇧H` でも切り替えられます。
- 「常に最前面に表示」をオンにすると、メインウィンドウの大きさと位置を保ったまま、ほかのアプリのウィンドウより手前に固定します。一覧右上のピン、メニューバーアイコンのメニュー、アプリの「ウインドウ」メニュー、Dockアイコンの右クリック（または長押し）メニューから切り替えられます。ショートカットは `⌥⌘P` です。オン・オフは各操作場所で連動し、再起動後も保持します。
- タスクはこのMacのユーザー領域に自動保存され、再起動後も残ります。

## 定期タスク

「タスクを追加」の「繰り返し」で「毎週」「毎月」を選ぶと、各回に締め切りが付く定期タスクを作成できます。タイトル・分類・URL・優先度を各回に引き継ぎます。

- 毎週：曜日を1つ以上選びます。月・水・金など複数指定できます。
- 毎月：1〜31日から日付を選びます。その日付が存在しない月は月末にします。毎月31日なら1/31 → 2/28（閏年は2/29）→ 3/31です。
- 開始日は任意です。未設定なら今日から、指定した場合はその日以降で条件に合う最初の日から生成します。作成時に過去分は生成しません。
- 起動中は30日先までのタスクを自動生成します。前回分が未完了でも次の回を作ります。アプリを終了していた間の未生成分は、次回起動時に補います。
- サイドバーまたはメニューバーの「定期タスク」から自動生成を停止・再開し、ルールを削除できます。停止・削除しても生成済みタスクは残ります。再開時は停止中の過去分を作りません。
- 管理画面での優先度変更は、生成済みの未完了タスクにも反映します。各回の締め切り・優先度はタスク一覧で個別に変更できます。完了・削除した回は再生成しません。

## 保存場所

タスクはmacOSの `UserDefaults` にローカル保存します。タスク管理にはアカウント登録やネットワーク接続は不要です。プレビュー時には一般ページのリンク先、またはSlack・Notionの公式APIにアクセスします。認証トークンはこのMacのキーチェーンに保存し、取得した本文はディスクへ保存しません。

## Gitに含めるファイル

ソースコード、`Package.swift`、`App/Info.plist`、README、ビルド・検証スクリプトと検証用データを管理します。検証コード内の認証値は模擬データです。

`.build/`・生成されたアプリ・IDEの個人設定・`.env`・OAuthクライアントJSON・秘密鍵・ローカルデータ・ログは `.gitignore` で除外します。作業用のデータ書き出しは `local-data/` または `exports/` に置いてください。認証トークンはキーチェーン、タスクやビュー設定はユーザー領域の `UserDefaults` に保存され、リポジトリには含めません。

## Slack・Notionの連携

サイドバー左下またはメニューバーの「連携設定」を開いてください。アプリの作成、権限、トークンの取得、ページの接続、保存までの具体的な手順と公式リンクをアプリ内に掲載しています。

- Slack：User OAuth Token（`xoxp-`）を使用します。必要なUser Token Scopesは公開チャンネル `channels:history`、非公開チャンネル `groups:history`、DM `im:history`、グループDM `mpim:history` です。自分が使う範囲のみ設定し、インストール後にトークンを登録してください。サーバー、Client Secret、Redirect URLの設定は不要です。
- SlackのレガシーBot・Webhookは使用しません。新規Slack AppのUser OAuth TokenとHTTP Web APIによる読み取りなので、レガシー機能の社内利用禁止には依存しません。
- Notion：Internal connectionの読み取り用トークンを使用し、ページを接続へ共有します。Read contentのみを有効にしてください。対象は `notion.so` / `notion.site` / `notion.com` のページURLです。
- 各サービス1ワークスペース分です。自動OAuthログインやトークンの自動更新は行いません。失効時はトークンを再登録してください。
- Slackはリンクしたメッセージ1件、Notionは先頭30ブロックのテキストを最大2,400文字表示します。添付・入れ子・コメントなどは元のリンクで確認してください。
- 「接続を確認して保存」は認証確認後にキーチェーンへ保存します。対象メッセージ／ページの閲覧権限は、そのURLのプレビューで確認してください。

## Googleカレンダーの予定表示

Google Calendar APIから直接取得します。一覧上部の「予定」から「非表示」「今日」「今日から7日間」「明日から7日間」を選べます。「終日予定を含める」「終了した予定を隠す」も設定でき、ビューに保存できます。

広いウィンドウでは予定を右側、狭いウィンドウではタスク一覧の下に表示します。予定を表示しても、サイドバーと操作メニューは画面内に残ります。カレンダーの選択自体は「連携設定」で行い、すべてのビューで共有します。

初回設定の詳しい手順は、アプリの「連携設定 → Googleカレンダー → 初回設定の手順」に掲載しています。

1. Google Cloudでプロジェクトを作り、Google Calendar APIを有効にします。
2. Google Auth Platformで同意画面を設定します。Workspace内で使う場合はInternal、ExternalのTestingモードなら自分のアカウントをテストユーザーに追加します。
3. 読み取り専用の `calendar.calendarlist.readonly` と `calendar.events.readonly` スコープを設定します。
4. OAuthクライアントを「デスクトップ アプリ」として作成し、JSONをダウンロードします。
5. アプリの「設定JSONを読み込む」でファイルを選び、「Googleでログイン」から標準ブラウザで許可します。
6. 「表示するカレンダー」の選択ボタンを押して表示対象を選びます。固定サイズのポップオーバー内でスクロールでき、カレンダー名・アカウントでの検索や「選択済みのみ」の絞り込みが使えます。初回はメインカレンダーを自動選択します。

[Google公式：デスクトップアプリのOAuth設定](https://developers.google.com/identity/protocols/oauth2/native-app)に従い、PKCE・stateとIPv4ループバックの一時ポートで認証します。Mac標準カレンダーの同期・アクセス許可、APIキー、Webサーバー、Redirect URIの手動登録は不要です。認証設定とトークンはキーチェーンに保存し、有効期限前にアクセストークンを自動更新します。ExternalのTestingモードでは通常7日で再ログインが必要です。Google Workspaceのアプリ利用制限がある場合は管理者に確認してください。

選択したカレンダーを1分ごと・アプリに戻ったとき・手動更新時に取得します。共有・繰り返し・終日・日またぎ予定に対応し、辞退・キャンセル済みを除外します。ページ分割された予定も取得します。Googleの認証が失効した場合は再ログインを案内します。

連携できるGoogleアカウントは1つです。予定の内容はメモリ上だけに保持し、選択したカレンダーと表示設定のみをローカル保存します。連携解除はこのMacのトークンを削除し、OAuthクライアント設定は再ログイン用に残します。Google側の認可も失効させたい場合は、Googleアカウントのサードパーティ接続で取り消してください。

## 振り返り

サイドバーの「振り返り」で、7日・30日・90日間の進み方を確認できます。仕事／プライベートと、定期タスクを含めるかどうかで絞り込めます。「プライベートを隠す」は集計・グラフ・一覧にも適用します。

- **長期間オープンなタスク**：振り返りの上部に、7日以上未完了のタスクを表示します。7〜13日は「要確認」、14〜29日は「要注意」、30日以上は「長期滞留」として注意を強め、経過日数と件数を表示します。期限なしでも対象です。集計期間の外で作ったタスクも含め、古い順に表示します。最初は3件で、「すべて」を開くと残りも確認できます。クリックすると編集でき、完了したタスクは注意表示から外れます。日数は作成からの経過時間を24時間で割って数え、未来の回として生成済みの定期タスクと非表示中のプライベートタスクは除きます。
- **完了数と前期間比較**：現在完了しているタスクを最終完了日で集計します。
- **完了までの時間**：作成から完了までの中央値・平均・90%の値・時間帯別の分布を表示します。待ち時間を含む経過時間で、実作業時間ではありません。
- **日々のペース**：日別の完了数と追加数、1日あたりの完了数、完了のあった日数が分かります。グラフの日付をクリックすると、その日に完了したタスクを確認できます。
- **期限内完了率**：期間中に完了した期限付きタスクのうち、期限の日付までに完了した割合です。
- **次に動かすタスク**：現在の未完了数・期限超過数・作成から7日以上の件数と、長く残るタスクを表示します。クリックして内容・期限・優先度を編集できます。未来の回として生成済みの定期タスクは、この見直し候補から除きます。

集計対象はこのMacに残っているタスクです。未完了へ戻したタスクや削除済みタスクは完了数から外れ、再完了した場合は新しい完了日へ移ります。過去の数値も現在の記録に応じて変わります。完了日時がない旧タスクは期間集計から除き、作成より前の完了日時を持つタスクは時間集計から除きます。除外件数は「集計の見方」で確認できます。

期間は今日を含む日数で、前期間は直前の同じ日数です。1日あたりの完了数は休日を含む全日数で割ります。定期タスクの経過時間は自動生成時刻から数えるため、単発タスクとの比較には「定期タスクを含める」をオフにしてください。期限内完了率は現在保存されている期限を使います。

## 連携処理の検証

```sh
./check-integrations.sh
```

実際の認証情報や外部APIを使わず、模擬レスポンスでURL解析・Slack本文と返信・Notion本文・権限エラー・回数制限を検証します。キーチェーンはテスト専用の一意な領域で保存・読み出し・更新・削除を確認します。

締め切りの保存・旧データ互換性・日付境界・並び替え・一覧の絞り込みは `./check-deadlines.sh` で検証できます。タスクデータの読み書きは行いません。

定期タスクの曜日・月末・閏年・30日先までの生成・再起動時の重複防止・停止／再開・旧データの移行・優先度は `./check-recurring-tasks.sh` で検証できます。保存の検証にはテスト専用の一時領域を使い、実際のタスクデータには触れません。

タイトル・内容の編集、空タイトルの拒否、編集下書き、完了日時の記録・並び順、再完了、日時を持たない旧データ、定期タスクの各回の編集は `./check-task-editing.sh` で検証できます。テスト専用の一時領域を使い、実際のタスクデータには触れません。

予定表示の期間境界・終日予定・日またぎ・並び順・夏時間は `./check-meetings.sh` で検証できます。カレンダー権限や実際の予定データは使いません。

Google OAuthのPKCE・state・ローカル応答・キャンセル・トークン交換／更新・カレンダーAPIは `./check-google-calendar.sh` で検証できます。ブラウザや実際のGoogleアカウントを使わず、ループバック接続と模擬APIで確認します。

ビューの移行・保存・切り替え・下書き・破損データ保護、複数条件ソートの優先順・反転・未設定値、長期未完了の7/14/30日境界、フィルター、振り返りの日付境界・中央値・プライバシー・定期タスク・夏時間は `./check-workspace.sh` で検証できます。テスト専用の一時保存領域を使用します。
